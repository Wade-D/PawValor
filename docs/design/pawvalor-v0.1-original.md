# 《萌爪骑士团》Pawvalor — 项目设计与开发交接文档 V0.1

**项目阶段：** 前期策划完成，准备进入技术原型开发  
**开发引擎：** Cocos Creator + TypeScript  
**目标平台：** 微信小游戏  
**游戏类型：** 竖屏、单英雄、自动攻击、轻度动作肉鸽  
**核心参考：** 《弓箭传说2》，同时参考《哈迪斯》的构筑多样性  
**中文名称：** 萌爪骑士团（已确认）  
**英文暂定名称：** Pawvalor

---

## 1. 游戏核心定位

《萌爪骑士团》是一款以可爱动物骑士为主角的竖屏肉鸽游戏。

玩家选择一名萌宠骑士进入关卡，通过移动走位、自动攻击、随机天赋选择和武器进化，击败敌人并挑战最终 Boss。

游戏主要面向休闲玩家，强调：

- 简单操作、低学习成本。
- 远程自动攻击，降低近战压力。
- 每位英雄拥有独特武器。
- 每位英雄拥有三条不同的核心进化路线。
- 主路线锁定，副流派可以自由混搭。
- 天赋组合、元素附魔和终极进化产生明显的战斗变化。
- 单局约 8–10 分钟，可反复游玩。

**最重要的差异化：同一个英雄可以通过不同的主路线、副机制和通用天赋，形成明显不同的战斗玩法。**

### 已经取消的设计

不再采用三骑士同时战斗、伙伴跟随、援护 AI、小队碰撞及伙伴羁绊系统。

**每局只有一名英雄独立作战。**

## 2. 游戏美术与镜头

### 2.1 美术风格

- 精致、可爱、明亮的 2D 像素风格。
- Q 版萌宠骑士，大头短身比例。
- 中世纪奇幻世界观。
- 铠甲、武器、披风等装备具有较高辨识度。
- 猫咪角色为主，逐步加入柴犬、兔子、狐狸等动物。

### 2.2 镜头表现

采用 **2D 伪45°俯视角**，不使用真实 3D 镜头倾斜或复杂等距地图。

具体实现：

- 逻辑上使用普通 2D XY 坐标系。
- 摄像机使用 2D 正交视图。
- 角色和场景资源绘制成斜俯视视觉。
- 根据脚底 Y 坐标处理前后遮挡。
- 使用地面阴影模拟角色空间关系。
- 保持普通矩形地图坐标，不需要菱形等距格子。

### 2.3 角色与地图比例

重点参考《弓箭传说2》的场景布局。

此前生成的效果图存在角色和怪物过大、可活动区域不足的问题，因此正式开发时应：

- 缩小角色和普通怪物的屏幕占比。
- 扩大可见战场面积。
- 提供足够的走位、躲避与弹道观察空间。
- 保持技能特效清晰，不让华丽美术影响操作判断。

设计分辨率暂定 720×1280，后续根据手机适配方案确定。

## 3. 角色动画与攻击实现

### 3.1 动画方案

采用 **人物和武器一体化的序列帧动画 + 独立远程攻击特效**。

暂时不采用身体、手臂、武器分离的复杂骨骼方案。

第一阶段：

- 正面、背面、侧面基础动作。
- 左右方向可以适当镜像复用。
- 每种武器制作少量挥动或施法序列帧。
- 根据目标角度选择最接近的角色朝向。
- 实际弹道按照 360°精确角度发射。

例如剑士自动锁定右上方敌人：

角色播放对应方向的挥剑动作，独立剑气沿目标的精确方向飞行。

### 3.2 自动攻击原则

- 玩家通过虚拟摇杆移动。
- 角色自动寻找攻击范围内的敌人。
- 可以边移动边攻击，不强制停下来攻击。
- 主角拥有自动攻击间隔。
- 攻击方向根据目标位置计算。
- 支持普通攻击、特殊弹道、命中效果与天赋触发。

## 4. 英雄与武器设定

角色绑定武器类型，不允许所有英雄自由使用所有武器。

但可以在对应武器类型内部扩展装备品质、外观与数值成长。

### 首批规划的六位英雄

| 英雄 | 动物 | 武器 | 三条主路线 |
|---|---|---|---|
| 雷恩 | 灰猫 | 长剑 | 万剑流、雷霆流、回旋剑流 |
| 露娜 | 白猫 | 魔法权杖 | 炎爆流、冰霜流、奥术流 |
| 莉莉 | 奶猫 | 圣光战锤 | 地裂震荡流、圣光审判流、神圣壁垒流 |
| 巴顿 | 柴犬 | 刀盾 | 无限弹射流、旋转盾阵流、铁壁反击流 |
| 米娅 | 兔子 | 长弓 | 箭雨连射流、致命狙击流、剧毒陷阱流 |
| 塞恩 | 狐狸 | 长枪 | 幻影枪阵流、破甲处决流、龙枪风暴流 |

以上六位是内容规划，不代表 MVP 必须全部制作。

### 武器基础攻击

长剑：挥剑发射远程剑气。

长枪：向目标方向释放直线穿透枪芒。

刀盾：投掷具有往返伤害的魔法飞盾。

长弓：快速发射远程箭矢。

魔杖：自动释放追踪或直线魔法弹。

圣锤：挥锤释放远程圣光震荡波。

**原则：所有英雄的基础攻击都应具备远程输出能力，不强迫休闲玩家靠近敌人。**

## 5. 核心肉鸽天赋系统

正式采用：

**主路线锁定 + 副流派自由混搭**

完整构筑由以下内容组成：

1. 一条主进化路线。
2. 一种主路线分支。
3. 一个与主路线对应的终极进化。
4. 有限的副机制与跨流派组合。
5. 可以升级的通用数值天赋。
6. 元素附魔与同属性共鸣。

### 5.1 固定进化节点

| 等级 | 事件 | 规则 |
|---|---|---|
| Lv.1 | 初始技能 | 获得英雄绑定武器的基础攻击 |
| Lv.2 | 普通升级 | 随机三选一 |
| Lv.3 | 主路线选择 | 三选一，锁定主路线 |
| Lv.4–6 | 自由成长 | 随机获得通用天赋与副机制 |
| Lv.7 | 主路线分支 | 当前主路线的两种分支二选一 |
| Lv.8–10 | 自由成长 | 强化已有构筑 |
| Lv.11 | 终极进化 | 必定获得主路线对应终极技能 |
| Lv.12+ | 后期强化 | 继续加强攻击、附魔和现有机制 |

Lv.3、Lv.7 和 Lv.11 属于特殊成长节点，不依赖随机抽取。

**Lv.3 决定终极技能类型，Lv.7 分支决定终极技能的具体行为。**

例如雷恩：

- Lv.3 选择万剑流。
- Lv.7 选择散华或聚锋。
- Lv.11 进化为万剑归宗。
- 散华版本形成大范围扇形剑阵。
- 聚锋版本形成集中攻击的高伤害剑阵。

主路线不会在一局中途改变。

### 5.2 副流派规则

不同主流派可以共享一部分兼容的战斗机制。

例如：

- 万剑流 + 雷霆刻印。
- 万剑流 + 追踪剑气。
- 回旋剑流 + 雷电效果。
- 炎爆流 + 寒冰附魔。
- 弓箭连射流 + 毒素攻击。

但玩家不能同时获得两条主路线的完整终极进化。

跨流派只能借用部分技能机制，不能替代主路线的独特性。

副机制槽位初步规划最多两个，具体与元素系统的关系仍需要在配置设计时统一。

### 5.3 跨流派组合激活规则【已确认】

当玩家获得符合特定组合前置条件的技能后：

**该组合在下一次升级时免费激活，不占用普通三选一选择机会。**

例如：

拥有指定雷电技能与剑气强化后，满足「雷霆剑雨」的组合前置条件。

下一次升级时自动解锁对应组合效果。

这一机制用于奖励玩家主动构筑特定的技能组合。

首版可以考虑的组合类型：

- 雷霆剑雨
- 炎狱破军
- 霜刃剑阵
- 致命贯星
- 雷暴连锁
- 炎枪领域

具体每个组合的技能 ID、前置等级、触发条件和倍率需要独立配置。

组合解锁必须具备幂等性，同一个组合不能重复激活。

### 5.4 元素附魔规则【最新确认】

元素种类包括：

- 火焰：灼烧、持续伤害。
- 寒冰：减速、冰冻或冰晶破碎。
- 雷电：追加雷击、连锁伤害。

**最新规则：最多允许两种元素附魔同时触发。**

这条规则覆盖早期“最多一种元素刻印”的设计。

具体要求：

- 英雄主路线自带的属性不能被附魔覆盖。
- 相同属性触发元素共鸣，强化原有效果。
- 不同属性增加额外命中效果。
- 不允许无限元素触发连锁。
- 衍生元素伤害默认不再次无条件触发相同元素效果。

待明确的实现细节：角色主属性是否计入“两种附魔同时触发”的上限，以及元素附魔与两个副机制槽之间的占用关系。实现之前先在配置模型里统一，不得沿用旧版单元素限制。

## 6. 通用天赋系统

通用天赋不改变英雄的主要技能形态，而是强化基础能力。

首版规划：

| 天赋 | 初始测试效果 | 上限 |
|---|---|---|
| 攻击强化 | 每级攻击伤害 +10% | 5 |
| 迅捷攻击 | 每级攻速 +8% | 5 |
| 精准暴击 | 每级暴击率 +5 个百分点 | 4 |
| 致命一击 | 每级暴击伤害加成 +20 个百分点 | 3 |
| 穿透强化 | 适用弹道穿透 +1 | 2 |
| 弹道扩大 | 弹道范围 +10% | 3 |
| 射程提升 | 射程 +12% | 3 |
| 范围增幅 | 技能范围 +10% | 3 |
| 生命强化 | 最大生命值 +12% | 3 |
| 轻盈步伐 | 移动速度 +6% | 3 |
| 坚韧护甲 | 受到伤害 -6% | 3 |
| 额外弹体 | 增加一个削弱后的攻击弹体 | 1 |

以上数值仅作为第一轮测试参数，尚未进行平衡验证。

## 7. 天赋抽取规则

普通升级采用随机三选一。

抽取步骤：

1. 获取当前英雄、主路线、分支、已有技能。
2. 构建当前可用的天赋池。
3. 检测技能前置条件。
4. 排除满级、不兼容、互斥与无法获得的技能。
5. 根据天赋品质与当前构筑计算抽取权重。
6. 生成三张不同的技能卡供玩家选择。
7. 更新角色属性及战斗行为。
8. 检查新满足的跨流派组合条件，安排下一次升级免费激活。

建议规则：

- 与主路线协同的天赋提高抽取权重。
- 已拥有副机制的升级卡适当增加权重。
- 每局暂定拥有 2 次免费刷新。
- 第 3、7、11 级固定进化不能刷新。
- 正常升级应尽量至少出现一张与当前构筑相关的卡。
- 如果合法候选不足，需要加入可用的基础属性强化作为兜底。

严格区分“天赋合法性过滤”和“随机权重选择”，两者不能混在一起。

## 8. 技能兼容与性能规则

所有攻击按逻辑类型分类：

- 直线弹道。
- 追踪弹道。
- 往返弹道。
- 弹射弹道。
- 环绕弹道。
- 范围爆炸。
- 持续伤害区域。

具体规则：

- 部分弹道机制互斥，例如同一实体不能无规则地同时采用多种运动控制器。
- 分裂、弹射、爆炸等衍生攻击需要限制递归。
- 分裂生成的新弹体不能无限再次分裂。
- 元素伤害不能无限触发新的元素伤害。
- 命中需要区分直接命中和衍生伤害。
- 每个技能可以配置触发冷却、最大触发次数和目标命中间隔。
- 大规模弹道需要通过对象池优化。

主技能、追加技能和范围领域要明确各自可以继承哪些天赋修饰。

## 9. Cocos Creator 技术架构

建议采用 TypeScript + 数据驱动设计。

核心模块：

| 模块 | 功能 |
|---|---|
| GameManager | 单局游戏流程、暂停和结束 |
| PlayerController | 玩家移动、生命、状态 |
| EnemyManager | 敌人生成、更新与回收 |
| TargetingSystem | 自动索敌 |
| AttackEmitter | 根据配置生成攻击 |
| ProjectileSystem | 管理剑气、枪芒、箭矢等弹道 |
| DamageSystem | 伤害、暴击、防御与命中 |
| StatusEffectSystem | 灼烧、寒冷、雷纹、破甲等 |
| TalentManager | 天赋拥有状态与升级 |
| SkillRoller | 随机卡池与权重抽取 |
| BuildManager | 主路线、副机制和构筑状态 |
| SynergyResolver | 跨流派组合条件与激活 |
| EvolutionSystem | 固定等级进化 |
| CombatEventBus | 攻击、命中、击杀及技能触发事件 |
| UIManager | 战斗 HUD、三选一、进化界面 |

建议用 JSON 或 TypeScript 配置表保存：

- 英雄基础属性。
- 武器攻击参数。
- 弹道类型与行为。
- 天赋与技能前置关系。
- 主路线进化。
- 跨流派组合条件。
- 伤害系数。
- 状态效果与触发规则。

避免将技能规则硬编码到每个英雄的控制脚本中。

### 性能优化

- 怪物使用对象池。
- 子弹与特效使用对象池。
- 使用空间哈希网格减少碰撞候选数量。
- 大部分碰撞使用简化圆形、矩形或线段检测。
- 怪物 AI 可以采用固定频率更新。
- 不做不必要的高频 Y 轴排序。
- 减少攻击实体数量，复杂特效优先采用视觉合并。
- 在微信小游戏真机上测试低端设备性能。

首轮建议以中端设备 60FPS、较低性能设备稳定 30FPS 作为优化目标，而不是提前承诺具体怪物数量。

## 10. 单局战斗循环

基本流程：

选择英雄 → 进入地图 → 自动攻击怪物 → 击杀获得经验 → 升级三选一 → 选择主路线 → 获得副机制 → 路线分支 → 终极进化 → 击败 Boss → 结算 → 返回主界面。

关卡初版建议：

- 单局目标 8–10 分钟。
- 1 张童话森林地图。
- 5 种普通怪物。
- 1 种 Boss。
- 通过关卡时间与玩家成长调整刷怪强度。
- 中后期有精英怪或较高强度怪物波次。

首版不必实现复杂随机地图生成，可使用固定场景与动态刷怪。

## 11. MVP 开发范围

第一阶段只制作 **雷恩一位英雄**，但要完整跑通三条核心进化路线。

### 必须实现

**基础战斗**

- 2D 伪45°视角场景。
- 主角八方向自由移动。
- 完整角色序列帧动画。
- 自动锁敌。
- 自动远程剑气攻击。
- 怪物受击、死亡、经验掉落。
- 主角生命、受伤、死亡。
- 对象池及基础碰撞优化。

**肉鸽成长**

- 基础经验升级。
- 普通天赋三选一。
- Lv.3 主路线选择。
- Lv.7 主路线分支。
- Lv.11 终极进化。
- 通用天赋强化。
- 兼容副机制获取及升级。
- 元素附魔和共鸣。
- 跨流派组合满足条件后免费激活。

**雷恩的三条路线**

1. 万剑流：多重剑气 → 散华/聚锋 → 万剑归宗。
2. 雷霆流：雷纹附魔 → 连锁雷击/雷霆贯心 → 雷神审判。
3. 回旋剑流：回旋之刃 → 护体飞剑/追魂剑 → 无尽剑轮。

**测试目标**

- 同一个英雄三条路线具备不同战斗体验。
- 固定进化不会因随机抽卡失败。
- 兼容性过滤准确。
- 不会出现无法使用的天赋。
- 组合技能只激活一次。
- 元素附魔符合最新双元素规则。
- 不存在无限技能触发循环。
- 连续多局可以正常初始化与重置。
- 真机运行稳定。

### 暂时不制作

- 其他五位完整英雄。
- 三骑士伙伴或援护系统。
- 复杂局外城堡建设。
- 公会、排行榜或 PvP。
- 大规模装备系统。
- 复杂随机地图。
- 完整商业化系统。

## 13. Codex 接手后的第一阶段工作

请先不要一次性开发整个游戏。

建议按以下顺序推进：

**阶段 1：建立项目骨架**
