## 1. 目标、范围与当前事实

提供独立于 Cocos 的纯 TypeScript 成长核心，验证经验获得、串行升级、合法候选过滤、普通三选一、刷新，以及 Lv.3/7/11 固定进化。核心输出可供后续界面使用的快照与命令结果。

用户已批准第三阶段分步推进：第一步实现成长核心；第二步接入属性实际生效、副机制和元素；第三步接入组合调度、中文界面与战斗整体验收。第一步的验收对象是规则与构筑状态，不能报告为可玩的天赋战斗已经完成。

已核实的基线提交为 `e0dccb9`，包含用户交接中提到的 `d353a18`。开始设计时，244 项测试、核心类型检查与依赖边界检查通过；现有战斗成长仍为 Lv.2 封顶。`build.ts` 已有构筑、待升级队列、选择与终极事件契约，但没有成长执行器。

第一步不接入 `DemoWorld` 或 Cocos 场景，不改变现有战斗 Demo。三条路线的攻击形态、元素伤害、副机制执行器、属性计算器、组合激活、界面和真机验证不属于本次交付。现有 `Bootstrap` 诊断保持原用途。

玩家可见名称及未来界面用语使用中文；新写代码注释和 Git 提交日志使用中文。保留 `client/.creator`、`client/extensions`、`client/settings` 本地目录。场景不需要修改；任何后续场景变更仍须通过 Creator/MCP 完成。

## 2. 方案及模块边界

采用现有的纯核心与适配层分工。第一步先完成核心；若同时接入战斗弹窗，玩家会遇到选择后属性尚未生效的状态，因此界面在效果执行器就绪后接入。一次实现完整战斗成长则会把三个步骤重新合并，扩大联调范围。

按职责划分少量模块，不引入完整 ECS、通用事件总线或空壳 Manager：

| 职责 | 输入 | 输出及约束 |
|---|---|---|
| 前置与合法性 | 配置、已提交构筑、可支持分类 | 合法候选及明确拒绝原因；不消费随机数 |
| 抽取 | 已过滤候选、权重、注入随机源 | 不放回抽取，输出不同 ID；不修改构筑 |
| 成长事务 | 经验、选择与刷新命令 | 串行队列、选择快照、构筑变更与终极事件 |
| 原型成长参数 | 显式经验阈值列表 | 有限等级上限；所有数值标记为测试参数 |

具体 API 和文件拆分在实施计划中确定。优先复用 `BuildState`、`GrowthState`、`RandomSource` 和 `UltimateEvolutionEvent`；以类型化选项表达天赋卡与独立奖励卡，不把兜底奖励伪造成天赋 ID。

`core/` 仅依赖核心内部类型与模块，配置通过构造参数注入。成长随机源与战场生成随机源分开，避免刷新卡片改变刷怪序列。核心可读配置必须拥有稳定内容，调用方后续修改输入对象不能改变已创建会话的规则。

## 3. 经验、等级与串行事务

经验分为累计获得量、已达到但尚未处理的目标等级，以及已提交构筑等级。初始构筑等级为 1；待选期间不提前提交目标等级。一次经验足够跨多级时，将新达到等级按升序加入队列且不重复入队。待选期间继续收到经验只补充队列，不覆盖当前选择。

经验曲线使用显式的“升至下一级所需经验”列表，便于测试和后续更换。第一步原型列表为 11 个值，每项均为 5，表示 Lv.1→2 至 Lv.11→12 每次需要 5 点经验，累计 55 点达到 Lv.12。保留 Lv.2 的 5 点门槛，并覆盖 Lv.11 后再次普通升级的路径。这是规则测试曲线，不代表战斗节奏、Boss 时间或平衡结论。实现必须接受注入不同的有效阈值列表；列表至少覆盖 Lv.11。

经验在配置最高等级的累计门槛封顶，多余经验丢弃；封顶不取消尚未提交的选择。输入经验允许有限非负数，包括小数；零经验不生成新等级。阈值必须有限且严格大于零，累计阈值必须可有限表示；非法输入在状态变更和随机抽取之前拒绝。

每次仅处理队首目标等级：

1. Lv.3 创建主路线选择；Lv.7 创建当前路线分支选择。
2. Lv.11 自动提交终极记录并输出一次终极事件，不产生普通选择。
3. 其他等级创建普通三选一。
4. 有选择时等待有效提交；提交成功后更新构筑等级并移除队首。
5. 自动处理下一个队首，直到需要选择或队列清空。

例如一次经验达到 Lv.12，核心仍须依次等待 Lv.2 选卡、Lv.3 路线、Lv.4—6 选卡、Lv.7 分支、Lv.8—10 选卡，自动授予 Lv.11 终极，再等待 Lv.12 普通选卡。不能按最终等级跳过中间节点。

第一步不调度组合；现有 pending/active 组合字段保持兼容。前置判定可以读取构筑中已存在的 active 组合 ID，但本步不会自动产生或激活组合。第二阶段战斗的暂停状态不复用为成长状态；未来适配器须在存在待选或待处理成长时停止战斗模拟。

## 4. 前置、合法性与抽取

第一步运行时仅开放 `general` 分类。附魔与副机制配置仍可被现有校验器检查，但不会进入本步抽取池，避免沿用尚未确定的槽位策略。新增分类以后必须显式启用并补齐其合法性规则。

前置按现有联合类型逐项判断，所有条件同时满足才通过：英雄匹配、指定天赋达到最低等级、路线匹配、分支匹配、指定组合已激活。前置与互斥属于合法性，不通过加减权重代替。

候选排除规则包括：不支持分类、前置不满足、已达天赋上限、与已拥有其他天赋共享互斥标签。已拥有天赋的自身升级不会因与自身标签重合而被排除。第一步没有强制的路线相关保底或额外权重加成；使用配置现有 `weight`，后续构筑相关性策略单独接入。

先确定合法候选，再对正权重候选加权不放回抽样。零权重表示不参加随机抽取；负数、非有限权重及非法配置阻止会话初始化。每张卡的权重只用于当次候选集合，抽中后移除；配置输入顺序固定时，同一随机序列产生同一结果。权重求和与采样不得因为有限大权重溢出而失效。

随机源必须返回 `[0, 1)` 内有限值。抽取在临时结果上完成，只有完整成功后才发布选择，失败不扣刷新次数、不替换旧选择、不修改构筑。随机源已被调用的次数无法通用回滚；复现失败后的重试需要使用相同的完整输入与随机源状态，不能声称失败命令完全回滚了外部随机源。

## 5. 候选不足时的独立强化奖励

正常普通选择始终提供三张不同卡。合法且正权重天赋少于三张时，保留全部可抽天赋，再从下列三种独立奖励中等概率、不放回补足缺额：

| 中文名称 | 记录的奖励 | 上限与解释 |
|---|---|---|
| 基础攻击强化 | 基础攻击伤害增加 1% | 可在不同升级重复获取，按次数累计 |
| 基础生命强化 | 基础最大生命增加 1% | 可在不同升级重复获取，按次数累计 |
| 基础移速强化 | 基础移动速度增加 1% | 可在不同升级重复获取，按次数累计 |

同一次三选一不出现相同奖励 ID 两次。独立奖励与名称相近的普通天赋是不同选项，奖励卡须带明确类型和中文说明。所有普通天赋均满级或被过滤时，提供上述三张奖励卡。

三种奖励单独存储非负整数获取次数，不计入 `talentLevels`、附魔位或副机制槽，也不用于满足“获得某天赋”的前置。未来执行器按未修饰基础值线性累计，每次增加基础值的 0.01 倍，不按当前值复利。本步仅记录奖励次数，不执行伤害、加血、移速或属性合并；最大生命提升时当前生命如何变化留给第二步的属性执行设计。

等级与经验上限使单局可选次数有界。兜底不会突破十二项通用天赋上限，不提供满级无效卡，也不通过普通天赋的权重影响兜底抽取。

## 6. 刷新与固定进化

每局刷新次数取现有 `growth.freeRerolls`，原型值为 2。刷新仅适用于当前普通选择；重新从当前已提交构筑计算候选并抽取完整三张卡，成功后扣一次。刷新可再次抽到原卡，甚至得到完全相同的三张；不额外排除上次结果。刷新重新生成选择版本，原卡命令立即失效。

没有次数、没有待选项、固定进化节点或旧选择令牌的刷新请求，均明确拒绝且不扣次数。固定节点不提供普通三选一、不消耗刷新。

Lv.3 按英雄配置的三条路线供选，提交后本局锁定。Lv.7 仅能从已锁定路线的两个分支中选择。Lv.11 必须已拥有正确的路线与其分支；记录终极已授予，输出包含路线、分支、终极效果和分支行为引用的 `UltimateEvolutionEvent`。终极基础效果与分支行为表示同一次进化，不能被后续执行器解释为无条件结算两次攻击。

本步将路线、分支和终极作为构筑记录与事件，不执行它们的战斗效果。不允许缺少路线/分支时悄悄选取默认值，或因错误状态退回普通选卡。

## 7. 命令、快照与生命周期

选择及刷新命令携带局次和选择版本；二者必须同时匹配当前待选状态。选项 ID 必须属于当前卡组，不能直接提交任意合法天赋或其他路线。

每次发布新选择或刷新成功都更新选择版本；成功提交立即使旧版本失效。重复提交、旧卡、非当前选项、旧局命令均返回类型化拒绝结果，不修改经验、构筑、队列、刷新次数或当前选项。程序配置和非法数值输入通过明确错误拒绝，面向界面的拒绝信息使用中文。

快照为只读且与内部状态分离，修改返回数组或对象不能修改会话。构筑快照包括已提交等级、路线、分支、天赋等级、独立奖励次数和终极授予记录；成长快照包括经验、封顶状态、待处理等级、当前选择和剩余刷新次数。

重开或重置时递增局次，清空经验、队列、选择、奖励、天赋、路线、分支、终极记录及待消费事件，并恢复本局刷新次数。选择版本不得使上一局命令重新匹配。成长实例须拥有独立会话标识，防止不同实例的相同局次与版本互相接受命令。随机源由调用方按新局种子创建或复位，不要求通用 `RandomSource` 暗含 reset 方法。

事件通过同步命令结果返回，不为本步添加订阅或异步回调。终极提交后只在导致该提交的命令结果中输出一次；读取快照或提交旧命令不重放终极事件。

## 8. 验收与风险

本步完成须满足：

1. `client/` 内 `npm.cmd run verify` 通过，已有第二阶段测试继续通过。
2. 新测试验证全部前置类型、满级排除、互斥与自身升级、分类隔离、零权重、无重复加权抽样、极端有限权重和固定随机源复现。

5. 覆盖重复/旧版本/旧局/跨实例命令拒绝、快照隔离、输入配置隔离、多次重置与随机源异常。
6. 新模块继续遵守纯核心依赖边界，新增资产脚本应有合法且唯一的 `.meta`；不手改 `.scene`。
7. 文档明确第一步仅完成规则层，战斗仍为原第二阶段 Demo。中文画面、触控、微信验证与 Cocos 许可问题仍需后续实际验证。

原型经验曲线和兜底奖励未经平衡测试；不得据此宣称成长节奏合理。第一步的通用池不包含元素、副机制，也不保证路线相关卡。后续扩大卡池时须补上槽位与兼容性规则；接入战斗前须确认无实际效果的卡不会作为可用战斗奖励展示。
