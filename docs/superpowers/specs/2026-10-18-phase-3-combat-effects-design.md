## 1. 目标、可见变化与边界

将已经提交的构筑转化为实际战斗效果，实现十二项通用天赋、三种独立基础强化、火冰雷附魔与共鸣，以及两种可升级副机制。交付沿用纯 TypeScript 核心与 Cocos 适配层分工，提供确定性测试及现有战斗场景内的中文效果测试预设。

本步完成后，用户可以在 `CombatDemo.scene` 切换预设，观察伤害、攻速、移动、穿透、额外弹体、灼烧、减速、雷击、追踪剑气和爆裂的变化。预设是开发测试入口，须明确显示“效果测试预设”，不能冒充正常选卡所得构筑。

**正式三选一弹窗、升级时暂停/选择后继续、战斗采用第一步的多级经验流程，以及组合在下一等级免费激活，仍在第三步接入。** 本步预设中的战斗经验继续沿用现有 Lv.2 上限，HUD 明确显示该限制；独立成长核心仍使用第一步的 Lv.12 测试曲线。不能把效果预设验收报告成完整升级闭环已经实现。

第四阶段承接完整万剑、雷霆、回旋剑主路线及分支/终极攻击形态。本步仅消费雷霆路线的固有雷属性以验证附魔与共鸣；不执行路线的弹道替换、分支攻击或终极。首批追踪剑气作为受限副机制，不授予整条追魂剑路线能力。

工作基线为 `4f08b60`，`codex/phase-3-growth-core` 已有 287 项测试通过。继续在该分支与工作目录推进，不自行合并。保留 `client/.creator`、`client/extensions`、`client/settings`；玩家可见文案、新写代码注释和提交日志用中文。场景序列化数据及 `.meta` 通过 Creator/MCP 操作，不手写 `.scene`。

## 2. 已确认的槽位规则

- 主路线固有元素不占附魔位，最多再获得两种附魔；雷霆路线可同时具有固有雷、火焰附魔与寒冰附魔三种属性来源。
- 两个附魔位与两个副机制槽相互独立。取得新附魔/副机制才占位，升级已拥有项不增加占槽。
- 固有元素与同属性附魔形成共鸣；同属性附魔仍占一个附魔位，不因为与固有属性相同而免费获得槽位。
- 不允许取得第三种附魔或第三个不同副机制，也不自动替换已有项。满槽时已有项的合法升级仍可出现。
- 前置、满级、互斥、槽位和实际能力兼容性先过滤，权重抽取仍只处理合法候选。候选不足沿用第一步的独立奖励补齐。

现有 `elementPolicy` 的两个布尔值与本次选择一致，但其 `test-only` 标记与注释不能继续表示“尚未决定”。实现应区分“已确认的槽位语义”和“未经平衡的原型数值”，同步类型、配置、校验及测试，不把数值升级为正式平衡参数。

## 3. 方案与模块职责

推荐扩展现有纯核心战斗，增加小型、职责明确的属性解析、触发预算和状态效果单元。只提供属性计算器不能证明效果在命中与时间推进中生效；建立完整通用技能框架则超出当前一英雄原型的需要。本步不引入完整 ECS、网络依赖或通用脚本执行器。

| 单元 | 责任 | 输出或约束 |
|---|---|---|
| 构筑与能力校验 | 检查构筑引用、等级、槽位和效果执行能力 | 非法构筑不得进入战斗；不能静默忽略已选但不支持的天赋 |
| 属性解析 | 从基础配置、天赋等级和奖励次数计算有效属性 | 可重复重算，结果不累计上次计算的浮点误差 |
| 触发限制 | 来源、深度、根攻击预算、效果冷却和目标间隔 | 不满足时不执行，不通过重置根 ID 绕过限制 |
| 效果执行与状态 | 直接伤害、派生伤害、灼烧、减速与副机制 | 使用模拟时间和实体代次，可测试与重置 |
| 成长候选扩展 | 按能力与槽位开放附魔/副机制 | 已有第一步只读快照可直接作为输入 |
| Cocos 表现 | 测试预设、中文说明、伤害与效果占位图形 | 从快照/事件读取，不在组件里计算伤害或前置 |

代码及数据继续在 `client/`，核心只依赖核心类型与显式注入的数据。具体文件与 API 在实施计划中确定。效果配置须明确表达触发时机、伤害倍率、半径、持续时间、跳伤间隔及减速比例，不通过天赋中文名称或任意 ID 字符串决定算法。

## 4. 属性计算与通用天赋

沿用原始十二项天赋的数值和等级上限，不新增复利语义。基础直接伤害为 `weapon.baseDamage + hero.attackPower × weapon.attackPowerScaling`，当前雷恩为 20。

同属性采用 `基础值 × (1 + 百分比增幅总和) + 固定增加总和`。`multiply` 配置值 1.10 表示每级增加基础值的 10%；独立奖励每次增加相应基础值的 1%，与对应通用百分比加算。例如二级攻击强化加三次基础攻击奖励，直接伤害为 `20 × (1 + 0.20 + 0.03) = 24.6`。

| 属性或天赋 | 执行语义 |
|---|---|
| 攻速 | 修饰每秒攻击频率，发射间隔为基础间隔除以攻速倍率；不补发历史攻击 |
| 暴击 | 暴击率与暴击倍率按原配置相加；概率钳制到 0—1；每次直接命中独立判定 |
| 穿透 | 穿透数为额外可命中的不同敌人数，数值 n 允许最多 n+1 次命中；同一弹体不重复命中同一实体代次 |
| 弹道扩大 | 同时扩大弹道显示尺寸与命中横向宽度，不能只放大图形 |
| 射程 | 同时作用于索敌与最大飞行距离；仍受配置寿命限制 |
| 范围增幅 | 线性扩大范围攻击的半径；无范围攻击能力时不进候选池 |
| 最大生命 | 重算后保持当前生命比例；死亡状态不因属性重算复活 |
| 移速 | 改变归一化移动意图对应的每秒位移，斜向不额外加速 |
| 护甲 | 减伤比例按配置相加并钳制到 0—1；最终受到伤害为原始值乘以剩余比例 |
| 额外弹体 | 同次发射增加一枚削弱弹体，其直接伤害为主弹体非暴击直接伤害的 60%；不削弱主弹体、不递归产生更多额外弹体 |

当前没有通用的无损恢复或复活天赋。伤害、生命、尺寸、速度与间隔必须为有效有限数，非法计算结果明确拒绝，不让世界状态进入 NaN/Infinity；生命/伤害结算保留数值精度，显示层可格式化到一位小数。

属性重算在新构筑提交后生效。发射中的弹体保留发射时伤害、穿透、尺寸、射程与附魔快照；已有灼烧保留自身伤害快照。攻速变化只影响下一次发射后安排的新间隔，不提前清空当前冷却。重复应用相同构筑不刷新效果冷却，也不改变生命比例。

弹道运动仍使用扫掠碰撞，多个命中按线段首次接触比例、实体 ID 排序。效果模式采用弹道宽度的一半扩大目标命中圆；没有效果构筑参数的原第二阶段兼容模式保留原来的点线段碰撞行为。额外弹体沿主弹体方向发射，起点向该方向左侧垂直偏移 0.2 世界单位并限制在战场内（测试参数），以便看到两枚弹体；它拥有独立实体和 attackId，支持实际命中、显示与清理。

## 5. 元素、升级与共鸣

元素伤害以触发弹体的非暴击直接伤害快照 D 为基准，包含其允许继承的攻击强化与弹体自身倍率，不再次套用主攻击暴击倍率。元素伤害和持续伤害本步不再独立暴击。附魔等级为 r 时，伤害倍率按 r 线性增长，持续时间和减速比例不随等级增加；固有元素没有附魔等级时按一级执行。

| 元素 | 一级普通效果 | 同属性共鸣的一级替代效果 |
|---|---|---|
| 火焰 | 每秒造成 `0.20 × D`，持续 3 秒 | 每秒 `0.30 × D`，持续 3 秒 |
| 寒冰 | 命中追加 `0.15 × D`，减速 30%，持续 2 秒 | 追加 `0.25 × D`，减速 30%，持续 2 秒 |
| 雷电附魔 | 命中追加 `0.30 × D` | 追加 `0.50 × D` |
| 雷霆路线固有雷 | 单独存在时追加 `0.40 × D` | 与雷电附魔共存时采用上一行共鸣，不再额外执行固有雷 |

上述倍率、持续时间、减速及间隔全部是原型测试参数。火、冰在现有雷恩配置中没有固有来源，共鸣仍须作为通用规则由合法测试配置覆盖。同属性共鸣使用附魔等级 r 对共鸣表倍率线性放大，不把固有、普通附魔和共鸣当成三次触发相加。

灼烧每 1 秒跳伤，首次在施加后 1 秒，三秒完整持续可跳三次。对同一敌人代次最多保留一份该英雄灼烧：重复施加延长到较晚的到期时刻，不能推迟已有的下一跳；更强伤害替换快照和归属根攻击，相等或更弱伤害只续期。到期时刻的最后一跳先结算，再移除状态。灼烧不能触发新的附魔、副机制或暴击。

寒冷只保留一份 30% 减速，不把多次命中叠乘成冻结；重施更新到较晚到期时刻。追加伤害仍须通过触发限制。状态在到期后清理；暂停和阵亡停止模拟时间，因此状态不在后台补跳。雷电本步为同目标追加伤害，不提前实现连锁雷击或雷霆终极。

## 6. 首批副机制与继承

两种副机制均可被兼容主路线获取，各上限三级，每种首次获取占一个副机制槽。每次受允许的直接命中按下表结算，伤害以同一次触发弹体的非暴击直接伤害 D 为基准。

| 副机制 | 原型效果 | 继承与限制 |
|---|---|---|
| 追踪剑气 | 命中位置产生一枚追踪弹体，伤害 `0.35 × r × D`；速度 10、寿命 2 秒 | 只继承攻击伤害、弹道尺寸和射程；不再暴击，不继承穿透、附魔或副机制 |
| 命中爆裂 | 在命中位置进行一次半径 1 世界单位的范围结算，伤害 `0.30 × r × D` | 继承攻击伤害和范围半径增幅；不再暴击，不继承附魔或副机制 |

追踪剑气从触发命中位置选择射程内最近的其他存活敌人，距离相同按实体 ID；排除刚刚被直接命中的实体。无目标时不生成弹体。目标失效后重新选择合法目标，无目标时沿最后方向飞行直至寿命/距离耗尽。每步最多转向当前目标一次，不瞬移；扫掠碰撞首次命中即销毁。

爆裂按当前存活敌人的中心到命中位置距离判断，可命中仍存活的原直接目标；按距离、ID 顺序结算。它是瞬时范围效果，不创建运动控制器，不按目标数量重复消耗触发次数。若直接命中已经击杀原目标，仍可按保留的命中位置产生爆裂或追踪剑气；不会把死亡敌人重新加入目标集合。

第一步配置中没有可获得的 `secondary-mechanism` 天赋，本步增加两项合法天赋、引用效果及必要参数校验，不把路线/终极效果直接复制为可抽完整技能。`area-size-up` 在拥有命中爆裂等范围攻击后才合法；条件属于可执行能力检查，不在权重层做伪过滤。

## 7. 根攻击与触发限制

同次基础发射的主/额外弹体共享 `rootAttackId`，各自拥有独立 `attackId`；直接来源为 direct、depth 0。衍生弹体、爆裂、元素追加和灼烧保留根 ID 并递增深度，不伪装成新的 direct。追踪剑气标记为 split，爆裂为 explosion，元素追加为 element，灼烧为 damage-over-time。

每种触发效果独立检查来源白名单、允许的触发来源深度、每根攻击次数、效果全局冷却和同目标间隔。首批附魔与副机制均只由 direct/depth 0 触发，每根攻击每种效果最多一次；元素冷却与同目标间隔为 0.25 秒，副机制两项各为 0.8 秒。额外弹体和穿透不能使同根攻击的同一效果无限多次触发。

火、冰、雷和两个副机制的计数及冷却分别隔离，不能让火焰用掉寒冰预算。规则先验证有效目标/效果，再消费预算；爆裂一次触发可作用于多个目标。已有状态的持续跳伤不重复申请施加预算，但仍带原根 ID 和实体代次。

只有对应根的弹体与状态全部消失后才清理根预算；效果冷却不能因根预算清理而提前归零。同目标记录包含实体 id+generation；重开清空根预算、冷却、状态、弹体和未消费事件，并递增局次。触发次数、深度与冷却均须有限，配置不允许无限哨兵值。

## 8. 战斗接入、事件顺序与重置

扩展现有战斗核心接受显式构筑/效果参数，未提供时保持第二阶段基础 Demo 兼容。效果构筑可以在 idle 或 paused 状态原子应用；运行中不能通过任意外部回调插入半次重算。该接口供本步预设和后续升级事务使用，不允许直接写内部天赋字典。

构筑校验包括英雄/天赋/效果引用、天赋整数等级与上限、奖励非负整数、类别 ID 列表与已拥有天赋一致、前置/互斥、槽位及已启用执行能力。配置和输入构筑深复制，只读快照与内部状态分离；非法更新不改变生命、冷却或已有弹体。测试预设注明构筑是人工注入，不声称它由当前 Lv.2 经验获取。

每步顺序沿用移动、刷怪/追击、接触伤害优先原则：读取上一步有效寒冷状态进行怪物移动 → 接触伤害并检查英雄死亡 → 发射/推进弹体 → 按顺序结算直接命中及击杀 → 对仍存活原目标施加元素 → 在保留的命中位置结算副机制 → 处理到期灼烧跳伤与状态清理 → 拾取经验 → 发布快照。英雄接触死亡时，本步后续攻击、状态伤害与经验均不执行。

副机制新生成的追踪弹体从下一固定步推进，避免在遍历弹体集合时递归追加并当步无限执行。派生伤害与直接伤害复用统一的伤害/死亡处理：每个敌人只击杀和掉落一次，不重复命中已死亡或被代次替换的实体。

暴击随机源与刷怪、成长随机源相互独立，按新局种子复位。状态与效果时间只依赖模拟时钟；重开、切换预设、销毁场景时清空新状态和表现节点，不产生旧局回调。

## 9. 中文测试预设与可见验收

在现有场景通过运行时节点提供五个中文按钮：“基础”“通用强化”“火冰雷”“雷电共鸣”“副机制”。切换时清空输入与固定步累积、清理节点并重建新局；不得在当前战局中途累积叠加预设。HUD 显示当前预设名、测试参数标记、有效属性摘要和“本入口暂为二级封顶”。

“基础”维持第二阶段规则。其他预设开启本步效果模式，使用生命 200、移速 1 的耐久测试怪物，其余战场调参沿用现有值，便于观察持续伤害与减速；这些调参集中配置，不写入正式平衡结论。

| 预设 | 注入内容与观察点 |
|---|---|
| 通用强化 | 攻击强化/迅捷攻击各二级，暴击率二级、暴伤一级，其余非范围通用天赋各一级；观察伤害、频率、穿透、尺寸、射程、生命、移速、护甲与额外弹体 |
| 火冰雷 | 固有雷路线 + 一级火焰/寒冰附魔；显示三个属性来源，观察灼烧、减速与雷追加 |
| 雷电共鸣 | 固有雷路线 + 一级雷电附魔；显示共鸣，验证只结算替代后的雷效果 |
