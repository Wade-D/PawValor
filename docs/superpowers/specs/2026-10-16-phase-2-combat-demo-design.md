# Pawvalor 阶段 2：基础战斗 Demo 设计

**状态：** 用户于 2026-10-17 批准。**依据：** [原始交接文档](../../design/pawvalor-v0.1-original.md)第 3、11 节及[已批准的阶段 1 设计](2026-10-15-phase-1-design.md)。

## 目标与边界

在 Cocos Creator 3.8.6 的 `client/` 内提供可预览的单局测试场景：玩家操作雷恩移动，雷恩自动向射程内最近的怪物发射直线剑气；怪物追击并接触伤害；剑气命中、击杀后掉落经验；拾取经验升至 Lv.2。死亡后可重开。此 Demo 用来验证最短战斗闭环、操作手感和 Cocos 适配边界，不作为数值平衡或真机性能结论。

用户已同意占位图及 **Lv.2 封顶**。Lv.3 必须选主路线，属于阶段 3，Demo 不能悄悄越级跳过它。Lv.2 后仍可继续战斗，经验不再增长，界面显示已达 Demo 上限。重开时清空本局进度。阶段 1 的 `Bootstrap.scene` 保持诊断用途；新增独立的 `CombatDemo.scene`，避免把配置校验页误当作战斗入口。

本阶段不实现天赋三选一、路线、分支、终极、元素、组合、Boss、完整序列帧、随机地图、服务端或上线资源。画面采用简单色块/图形占位和二维战场坐标；斜俯视素材尚不存在，不能宣称已经达到正式伪 45° 美术效果。

## 方案选择

选择**纯 TypeScript 模拟核心 + Cocos 输入/表现适配**。Cocos 每帧传入移动意图与时间，核心推进世界状态并返回快照、事件，Cocos 根据结果更新节点。这样可在 Node 中复现索敌、命中、升级与重开，沿用阶段 1 的核心依赖边界。

直接把所有规则写在场景组件中，初期文件少，但碰撞和升级只能依靠编辑器手测，也会破坏阶段 1 已建立的可测试边界。引入完整 ECS/物理框架则超过一英雄、一怪物原型的需要。故本阶段采用少量职责明确的核心单元，不预设未来通用战斗框架。

## 战场、操作与时间

- 固定 1280×720 设计分辨率；核心使用数值世界单位，适配层按 **64 屏幕像素 = 1 世界单位** 转换。可见战场为 20×11.25 世界单位，原点在中心。角色中心始终限制在战场内。
- 键盘支持 WASD 和方向键；触屏左下虚拟摇杆支持任意方向。两种输入同时存在时，活动触屏优先。输入向量大于单位长度时归一化，斜向移动不加速；失焦或触摸取消即归零。移动中持续自动攻击。
- 核心使用固定 `1/60` 秒模拟步；适配层累计帧时间，每帧最多补进 5 步，多余积累丢弃并记一次诊断，避免窗口切后台后发生大量瞬移/补发。暂停、死亡时不推进模拟时钟。随机源提供固定种子，使 Node 测试可重复。
- 场景包含开始/暂停/继续/重开控制以及可读 HUD：生命、等级、经验进度、已达上限、击杀数、状态。键盘 `R` 和触屏按钮均可重开。

## 战斗规则与测试参数

雷恩沿用 `rainePrototypeConfig` 中的生命 100、移动速度 5、武器间隔 0.8 秒、射程 8、剑气速度 12、寿命 1 秒、`pierceCount: 0`。世界单位与屏幕像素的换算只发生在适配层。一次直接攻击伤害取 `weapon.baseDamage + hero.attackPower × weapon.attackPowerScaling`，当前测试值为 20。阶段 2 不执行暴击、天赋、附魔或衍生攻击；不能把这些字段已存在误报为已实现。

- 核心按距离最近选取存活且在射程内的怪物；距离相同时按实体 ID 升序。若无目标，不发射且不积累可瞬间倾泻的多次攻击。剑气发射后保持发射方向，目标移动时不追踪。
- 一种测试怪物：生命 30、移动速度 2 世界单位/秒、接触伤害 10、同一怪物接触伤害间隔 1 秒。雷恩与怪物的接触半径均为 0.35 世界单位，中心距不超过 0.70 时发生接触。怪物直接追向雷恩；重叠时停在当前位置，不用未设计的寻路。每 2 秒在战场边缘生成一个，场上最多 12 个；新局先生成一个。生成点与雷恩至少相距 4 世界单位。以上均为显式标注的原型参数。
- 剑气和怪物用数值几何检测碰撞。每步使用弹道位移线段与怪物圆形命中范围（半径 0.35 世界单位）相交，避免高速弹道穿透；首次命中即结算 20 伤害并销毁剑气。怪物生命降至 0 只产生一次击杀与经验掉落。弹道到寿命或有效射程后清理，不命中死怪物。
- 怪物被击杀后在原地生成价值 1 的经验球。雷恩与经验球中心距离不超过 0.45 世界单位才拾取；死亡后不再拾取。升级阈值为累计拾取 5 经验，从 Lv.1 升至 Lv.2 后封顶。阈值和怪物数值均是可集中调整的 Demo 参数，不写回正式 `GameConfig` 作为平衡结论。
- 雷恩生命降至 0 进入失败状态，停止模拟；点击重开或按 `R` 先将核心重置为 idle，再开始新局。时钟、随机源、下一实体 ID、怪物、剑气、经验球、攻击冷却、接触冷却、输入和 HUD 均重置；跨局 generation 增加，即使新局重用相同数字 ID，旧局句柄也不匹配。重复重开不产生旧局残留节点或回调。

## 模块与数据流

`core/` 实现战场状态、固定步推进、数值碰撞和经验进度，不引用 `cc`、Node、DOM 或微信 API；它读取英雄/武器/剑气的已有配置字段和独立 Demo 参数，输出只读快照及本步事件。实体 ID 可复用时必须递增 generation；命中、击杀和拾取在结算前核对句柄，避免复用后的错误命中。阶段 1 的 `AttackSource` 在此只使用 `direct`、深度 0，攻击 ID 及根 ID 在新局重置。

`cocos/` 负责键盘/触摸输入、固定步调度、将世界坐标映射到节点、HUD 与占位图形、场景生命周期。进入战斗前运行现有 `validateGameConfig`；失败时阻止模拟并在 HUD/控制台明确列出配置错误。场景资源仅通过 Creator 编辑器或 Cocos MCP 创建、修改和保存，提交对应 `.meta`，不得直接改写序列化 `.scene` 文件。`server/` 仍只预留，不新增网络依赖。

事件顺序每固定步固定为：读取输入并移动雷恩 → 生成及移动怪物 → 接触伤害并立即检查死亡 → 存活时选择目标并发射 → 推进剑气及命中/击杀 → 掉落与拾取经验 → 升级状态 → 发布快照。若接触伤害使雷恩在本步死亡，本步跳过攻击、命中与经验拾取并发布失败状态。核心对非有限或负数 `dt`、非法输入向量给出明确错误，不让状态变成 NaN。

## 验收

1. `client/` 的 `npm.cmd run verify` 通过；核心测试覆盖斜向归一化、最近目标及 ID 平局、无目标不攻击、移动中攻击、剑气线段命中/射程/寿命、怪物只死亡一次、接触伤害冷却、经验球实际拾取、Lv.2 封顶、暂停/死亡停止推进，以及重开清理与固定种子复现。
2. Creator 3.8.6 中打开 `CombatDemo.scene` 无脚本/资源导入错误；键盘与触屏可操控，能观察到至少一轮自动攻击→击杀→拾取→Lv.2、受伤→死亡→重开。场景通过 MCP 验证且保存状态为干净。
3. 桌面预览记录截图或短录像及控制台结果。若无法自动验证触屏，明确列为手动待测；若未在微信真机运行，不报告真机 FPS。保持 `Bootstrap.scene` 配置诊断可用。

## 风险与后续决策

当前屏幕比例、占位视觉、怪物数量、伤害和经验阈值只用于可测闭环；正式地图比例、斜俯视素材、触屏手感、性能上限需用目标设备检验。Lv.2 封顶意味着不能用此 Demo 衡量 Lv.11 前的成长节奏。阶段 3 开始前仍需决定元素/槽位策略、普通卡不足三张的兜底、属性叠加与经验曲线；本阶段不替这些决策作隐含默认。
